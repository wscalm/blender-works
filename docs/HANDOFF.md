## 1. 最短の再開手順

```bash
cd /home/sowa/workspace/blender-works
./run_blender.sh scripts/build_all.py     # 約 10 分 (4096px・256 サンプル)。renders/*.png + models/room.blend + room.glb + room_lightmap.webp + room_glossmap.webp
./run_blender.sh scripts/build_all.py --samples 32 --size 2048 --no-render   # 形だけ急いで確かめるとき (約 55 秒。光がざらつく)
python3 tools/inspect_glb.py              # ノード名・三角形数 (今は合計 約 175,000 tris。多いのは毛布 (26,000)・キーボード・ワイシャツ・テレビ台のかご)
python3 tools/make_textures.py            # 色を合わせたテクスチャ (床・扉・壁紙・布・タオル地の敷きパッド) を textures/ に作り直す (元画像の色を変えたいとき)
python3 tools/make_prints.py              # 自作の画像 (本の背・モニターの画面・時計の文字盤・絵・賞状・絵本・ボーダー・かごの編み目・ティッシュの箱・ラグ) を textures/ に作り直す
python3 tools/make_boxes.py               # 出窓の段ボール箱2つ (実在の商品) の印刷 textures/box_tea.jpg・box_water.jpg を作り直す
python3 tools/make_guide.py               # renders/guide_plan.png (座標ガイド図) を作り直す
tools/serve.sh                            # ビューア用サーバー。別プロセス/バックグラウンドで起動 → http://localhost:8000/viewer/ を F5
```

- 形の確認は `renders/iso_se.png` `iso_sw.png` `iso_ne.png` `top.png` `eye_*.png` を Read で見る (昼のプレビュー照明。EEVEE)。
- **夜の見た目 (本番の見た目) はビューアのスクショで確認する** (§7)。`renders/` の画像は形の確認用で、照明は本番と違う。
- 標準の視点で細かく見えないときは `scripts/closeup.py` の `VIEWS` を書き換えて `./run_blender.sh scripts/closeup.py` →
  `renders/closeup_*.png` を Read → `rm renders/closeup_*.png`。
- ユーザーは自分のブラウザで `http://localhost:8000/viewer/` を見ている。**glb を作り直したら「F5 で再読み込み」と伝える**。

## 2. ユーザーについて・進め方

- 返答は **常に日本語** (グローバル CLAUDE.md)。
- ユーザーは家具の位置を **短い言葉で** 指示する (「ベッドの横、クローゼットと反対側」など)。写真はなく、間取り図 `reference/m_633004_10170_6.webp` のみ。
  家具の参考画像 (例: スツール `reference/864-g01-2.jpg`) は後から渡されることがある。
- 曖昧な指示は **こちらで妥当に解釈して作り、解釈と座標を明記して返す** (質問で止めない)。直しは `scripts/layout.py` の数値で済ませる。
- 指摘は具体的で、見た目の違和感が多い (「床をもう少し暗く」「魚眼が気持ち悪い」「ひじ掛けはもっとシンプル」「ローポリは安っぽい」)。
  直したら Blender の画像かビューアのスクショで **自分で見て確認してから** 報告する。
- 返答には、(1) 何をどう直したか (2) 座標 (X/Y の範囲・向き) (3) 解釈が分かれた点、を書く。X/Y/Z の軸の説明は `renders/guide_plan.png` と同じ言い方に揃える。
- **コミットはユーザーが求めるまでしない** (まだ1回もコミットしていない。全ファイルが untracked)。

## 7. 道具の使い方・落とし穴

### 照明の焼き付け (`scripts/lighting.py` → `scripts/bake.py`)

- 流れ: 確認画像を撮った後に、プレビュー照明を消して夜の照明にする → 全メッシュに UV `lightmap` を作る → 全メッシュの複製を1つに結合して Cycles (GPU, OptiX) で
  (1) 拡散光 (DIFFUSE の直接 + 間接、色なし) と (2) ツヤ (GLOSSY の直接 + 間接 + 色) を 4096px に焼く → コンポジターの Denoise (OIDN) →
  K で割って 8bit sRGB の WebP に保存 (`room_lightmap.webp` / `room_glossmap.webp`) → K と目の位置を glb の extras へ。
- ツヤは見る向きで変わるので、目の位置 (`layout.VIEW`) にカメラ `bake_eye` を置き、`bake.view_from = 'ACTIVE_CAMERA'` で焼く。カメラは動かないので正しく見える
  (`?mode=orbit` の俯瞰では映り込みの位置がずれるが、確認用なので気にしない)。ツヤの強さは各材質の `roughness` と `specular` (`make_material`)。
- ライトマップの UV (`add_lightmap_uvs`): 見える面だけ Smart UV Project (66°) で島に分け、島ごとに「実寸 × 目からの距離の重み `clamp(1.2 / 距離, 0.35, 2.5)`」の大きさで棚詰めする。
  目の近く (机の上) は細かく、遠い物は粗い。今は 4458 島・基準 318 px/m (重み込みで 111〜795 px/m。4096px のとき)。
  部屋の中から見えない面 (壁の外面・床の裏・天井の上) と、ガラス・発光する面は画像の隅の1点に潰す。
  Blender 標準の `uv.lightmap_pack` は割り付けが偏り (一部の面が画像の半分を占めた)、遅かったので使っていない。
- 明るさの調整: 照明そのものは `room_spec.CEILING_LIGHT` (`strength` `color`) と `lighting.py` の出窓の外の光 (`energy` 4)。
  見た目の明るさだけなら焼き直さずにビューアの `EXPOSURE` (`?exposure=3` で試せる)。
- 細い枠の縁に白い点が出たので、跳ね返り光の外れ値を `sample_clamp_indirect = 3` で抑えている。焼き付けの K は明るい方から 0.3% の値。
- 細い管 (S字フック・キーホルダーの輪・ハンガーのフック・カーテンのリングとフック・エアコンのコンセントの線) は島が 1px に満たず、焼いても画素が当たらないので **黒や色の点** に見えた。
  `props.tubes_object(..., light_from="近くの物の名前")` にすると (カスタムプロパティ `lightmap_proxy`)、島を作らずに全体を「借りる先の、目の側を向いた面で、管の中心に一番近い点」の UV に潰す
  (`bake._proxy_uv`)。レールの金具 → `hanger_rail_body`、カーテンのリング → `curtain_rod`、コンセントの線 → `room_outlet_aircon`
- 曲がった布 (カーテン・毛布・枕・クッション・トートバッグ) は、Smart UV が細かい島に分けると継ぎ目の画素が合わず、**まだらの継ぎ目やギザギザの欠け** に見えた。
  カスタムプロパティ `lightmap_uv` = 自分で作った重ならない展開の UV の名前 (`lightmap_seed`) を付けると、その展開で島を作る (棚詰めと大きさの重みは同じ)。展開の UV は焼いた後に消す。
  カーテン = ヒダに沿った布の展開、毛布 = 布の展開 + 厚みの裏面、`pillow_object` = 表と裏を1枚ずつ
- 布のツヤ (`specular`) を強くすると、グロスマップに白い点々や筋が出る。つや消しの布は `roughness=1.0, specular=0.12〜0.3`
- 布のヒダを細く深くすると (束ねたカーテン)、ヒダどうしの影で真っ黒に焼ける。ヒダの幅 >= 深さ くらいにする
- 落とし穴: 焼き先はメッシュの **アクティブな UV** (画像ノードにつないだ UV ではない)。物体ごとに焼くと物体の数だけシーンを準備し直して遅い (23個で 210 秒 → 結合して 18 秒)。

### ビューア (`viewer/index.html`, three.js r160 を CDN から)

- 操作: ドラッグ=見回し (少し遅れて滑らかに追う)、ホイール=ズーム (横 50〜110°)、家具クリック。`V` = 俯瞰 (確認用。天井とシーリングライトを隠す)。歩く操作は廃止した。
- 材質: glb の材質を MeshLambertMaterial に置き換える (`bakedMaterial`。シーンにライトは無いので、光は焼いた物だけ)。
  普通の物 = 色 × ライトマップ × K × π (three.js は lightMap を π で割るため) + グロスマップ × Kg (emissiveMap。ツヤ・映り込みを足す)。テクスチャは異方性フィルタを最大にする。
  ガラス = 暗い半透明。発光 (emissive) = その色 × 強さで光る (1 を超えると bloom でにじむ)。ホバー中の家具は色を 1.3 倍にする。
- ライトマップの PNG が無い (glb の extras に `lightmap_file` が無い) ときは、昔の仮の照明 (半球光 + 平行光) で表示する。
- クエリ: `?pos=X,Y` / `?pos=X,Y,高さ` `?look=north|east|south|west` `?at=X,Y,Z` (部屋の座標の点を向く) `?pitch=度` `?hfov=90` `?exposure=3` `?tone=aces` (既定 agx) `?post=0` (仕上げなし)
  `?mode=orbit` `?debug&probe=<ノード名>`。
- `?debug&probe=<ノード名>` はそのノードの中心をクリック判定して、当たった家具名か `none` を左上に出す。
  手前に別の物があるとそれに当たる (ソファーの裏のスツールを probe すると `sofa` になる。バグではない)。
- クリック判定は「画面の手前から最初に当たる不透明なメッシュ → 親をたどって `CLICKABLE` の名前を探す」。壁・ガラスで誤って遮られない。

### 落とし穴 (踏んだもの)

- Blender は **5.2**。2.9x/3.x 向けのコードは名前が違うことがある (CLAUDE.md の「注意」)。
- `run_blender.sh` は `WORKSPACE_WIN` を `WSLENV` 経由で渡している。スクリプトを増やすときも `./run_blender.sh <スクリプト>` で起動する。
- 面の法線は「反時計回りに見える側が表」。`mesh_object` で作った面が暗い/消える場合は頂点の順序を疑う (`solids_object` の8点は `boxes_object` と同じ並び)。
- 確認画像 (昼のプレビュー): Filmic や天井直下の点光源は白飛び・黒つぶれの原因になった。今は Standard + 面光源 + 環境光 (`views.setup_preview_lights`)。プレビューのライトは glb に出ない。
- glb 書き出しは `MESH` と `EMPTY` だけ (`use_selection`)。座標は Blender の Z-up → glTF の Y-up に変換される (ビューア側 `toThree(x,y,z) = (x, z, -y)`)。
  UV は `UVMap` → TEXCOORD_0、`lightmap` → TEXCOORD_1。シーンのカスタムプロパティは extras (`export_extras=True`)。
- ビューアで `pick()` を使うときは `matrixWorld` が古いことがあるので `updateMatrixWorld()` を先に呼ぶ (対応済み)。
- 視野角: 横 100° が上限の目安。105° を超えると魚眼のようになる (§4)。
- 家具のローカル座標は 原点=足元の中心 / 正面=-Y / 背面=+Y。`FACING_DEG` で向きを決める。ローカルの +X は、正面から見た人の右 = 座った人の左。
